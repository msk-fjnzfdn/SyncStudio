# Отчёт по проекту «SyncStudio»

## 1. Цель проекта

Разработать веб-приложение, позволяющее:
- преподавателям и ученикам совместно работать с кодом в реальном времени;
- учителю транслировать свой код всем ученикам комнаты;
- учителю просматривать и редактировать код любого подключённого ученика;
- выполнять код (Python, JavaScript, C++ через WebAssembly) прямо в браузере;
- управлять комнатами, участниками и ролями (администратор, учитель, ученик).

Проект ориентирован на образовательные цели: проведение онлайн-занятий по программированию.

---

## 2. Используемые технологии

| Компонент           | Технологии |
|---------------------|------------|
| Backend             | FastAPI (Python 3.10+) |
| Аутентификация      | OAuth 2.0 (Яндекс ID), JWT |
| База данных         | PostgreSQL, asyncpg, aiosql |
| WebSocket           | FastAPI WebSocket |
| Фронтенд            | HTML, CSS (custom), JavaScript (Vanilla) |
| Редактор кода       | Monaco Editor (VS Code core) |
| Запуск кода         | Pyodide (Python в WASM), самодельный раннер для JS |
| Миграции            | SQL-скрипты (up/down) |
| Статика             | Jinja2, CSS-модули |

## 3. Архитектура приложения

```
SyncStudio/
├── main.py                 # точка входа, роутинг страниц, lifespan
├── autentification.py     # OAuth Яндекс + JWT
├── room.py                # CRUD комнат, добавление участников
├── room_manager.py        # WebSocket-менеджер (состояние комнат)
├── dependencies.py        # Depends: get_current_user
├── jwt_utils.py           # создание / декодирование токенов
├── database.py            # пул соединений, aiosql-запросы
├── const.py               # переменные окружения
├── shemas.py              # Pydantic-схемы
├── queries/               # SQL-запросы (room_queries, user_queries)
├── static/                # CSS, JS (room, dashboard, pyodide-runner)
├── templates/             # HTML-шаблоны (base, dashboard, room, login)
└── migrations/            # SQL-миграции (000001…000005)
```

Ключевые взаимодействия:
- HTTP – страницы, создание комнат, настройки, добавление учеников.
- WebSocket – обмен кодом между учителем и учениками в реальном времени.
- JWT – хранение в `HttpOnly` cookie, автоматическое обновление access-токена.

## 4. Реализованная функциональность

4.1. Аутентификация и роли
- Вход через Яндекс ID (OAuth 2.0).
- При первом входе автоматически создаётся пользователь с ролью `ученик` (role_id=3).
- Роли: администратор (is_superuser=true), учитель (is_staff=true), ученик.
- JWT access + refresh токены (access – 24 ч, refresh – 30 дней).
- Защита эндпоинтов через `Depends(get_current_user)`.

4.2. Управление комнатами
- Только пользователи с `is_staff` могут создавать комнаты.
- При создании создатель автоматически добавляется в `room_user`.
- Уникальность названия комнаты для каждого учителя (триггер в БД).
- Настройки комнаты: изменение названия, максимального числа участников.
- Удаление комнаты (только создатель).
- Добавление учеников в комнату по username.

4.3. Совместная работа через WebSocket
- Учитель:
  - пишет код в своём редакторе → автоматическая трансляция всем ученикам;
  - видит список онлайн-учеников;
  - может «посмотреть код ученика» – открывается второй редактор;
  - может редактировать код ученика – изменения применяются у ученика в реальном времени.
- Ученик:
  - видит код учителя на отдельной вкладке;
  - пишет свой код, который учитель может просматривать;
  – получает уведомление, если учитель правит его код.
- WebSocket-менеджер хранит состояние каждой комнаты: `teacher_ws`, `students {id: {ws, code, lang}}`, `teacher_code`, `teacher_viewing`.

4.4. Выполнение кода
- Python – Pyodide (WASM), полная изоляция, перехват `print`.
- JavaScript – через `new Function()` с фейковым `console.log`.
- C++ – заглушка (планируется интеграция с WASM-компилятором).
- Результат выполнения отображается в панели вывода.

4.5. Интерфейс
- Dashboard: список комнат пользователя, индикатор заполненности (зелёный/жёлтый/красный), кнопка создания комнаты.
- Страница комнаты: сайдбар (язык, ученики онлайн, статус WebSocket), редакторы, панель вывода.
- Настройки комнаты: изменение параметров, список участников, удаление комнаты.
- Адаптивный дизайн – тёмная тема, минимализм, «киберпанк»-акценты.

## 5. База данных

Таблицы (основные)
| Таблица       | Поля |
|---------------|------|
| `role`        | id, name, is_superuser, is_staff |
| `user`        | id, email, username, role_id, yandex_id |
| `room`        | id, name, max_members, created_by |
| `room_user`   | id, user_id, room_id, path_to_file |

Триггеры и ограничения
- `check_admin_room_name` – запрещает учителю создавать две комнаты с одинаковым именем.
- Каскадное удаление: при удалении комнаты удаляются связи `room_user`.
- Уникальность `(user_id, room_id)` – один пользователь не может быть добавлен дважды.

Миграции
Все изменения идут через `up` / `down` скрипты (000001…000005), включая удаление поля `password` и добавление `yandex_id`.

---

## 6. Безопасность

- JWT хранятся в `HttpOnly` cookie – недоступны для XSS.
- Refresh-токен обновляет access-токен через `/auth/refresh`.
- Зависимости: все эндпоинты проверяют `get_current_user`.
- Права доступа: проверка `is_staff`, `created_by` для изменения/удаления комнаты.
- Валидация: Pydantic-схемы, ограничения в БД (max_members < 40).
- Защита от SQL-инъекций – параметризованные запросы через aiosql.

## 8. Тестирование (в ходе разработки)

- Ручное тестирование:
  - создание комнаты разными пользователями;
  - параллельное подключение нескольких учеников;
  - просмотр и редактирование кода ученика;
  - переподключение WebSocket;
  - запуск Python-кода (Pyodide).
- Известные ограничения:
  - C++ пока не поддерживается (заглушка);
  - удаление ученика из комнаты не реализовано на бэкенде (только фронт-заглушка);
  - файлы (uploads) не интегрированы полностью (только заготовка).
